# TA Tenders — агрегатор тендеров, донорских проектов и НПА

Публичный сайт + Telegram-канал для TopAdvisor: международные тендеры МФО
(Всемирный банк, TED/ЕС, UNDP, AIIB, ЕБРР), госзакупки Узбекистана
(TenderWeek, etender.uzex.uz), позиции экспертов и мониторинг законодательства
(lex.uz) — с LLM-разбором каждой позиции.

**Архитектура — полностью serverless, без VPS:**

```
GitHub Actions (cron 6×/день, минута :17 — на :00 GitHub опаздывает и теряет прогоны)
  └─ pipeline/ (Python): сбор → дедуп v3 → Haiku-фильтр → анализ карточек
       ├─ data/monitor.db      (SQLite, коммитится — «репо как база»)
       ├─ web/data/*.json      (экспорт для сайта, коммитится)
       │     └─ push → Vercel автосборка сайта (web/, Next.js SSG)
       └─ Telegram: короткие карточки + кнопка «Разбор на сайте»
```

Наследует uz-monitor-v2 (`TopAdvisor/7. News Database/`), главные отличия:
дедуп против истории и между категориями, вечный реестр НПА по реквизиту акта
(один акт = одна карточка, новости прикрепляются упоминаниями — повторов нет),
экспорт на сайт, хостинг без сервера.

## Локальный запуск

```bash
# Пайплайн
cd pipeline
cp .env.example .env          # заполнить ключи
pip install -r requirements.txt
python3 run.py --test         # проверка источников (шлёт тест в Telegram, если задан)
python3 run.py --collect      # только сбор, без LLM и Telegram
python3 run.py --run --no-telegram   # полный цикл без отправки
python3 run.py --run          # боевой цикл

# Сайт
cd ../web
npm install
npm run dev                   # http://localhost:3000
```

Без `ANTHROPIC_API_KEY` пайплайн работает в dry-режиме (эвристический скоринг).
`ANALYZE_MAX` в .env ограничивает число LLM-разборов за запуск (контроль затрат).

## Развёртывание (один раз)

1. **Перевыпустить ключи** — старые Telegram/Anthropic-токены из
   `7. News Database/News database/` скомпрометированы (лежали открытым текстом).
2. Создать **приватный GitHub-репозиторий**, запушить этот проект.
3. **Vercel** → Add New Project → импортировать репозиторий,
   Root Directory = `web`. Задеплоится статикой.
4. GitHub → Settings → Secrets → Actions: `ANTHROPIC_API_KEY`,
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `SITE_BASE_URL`
   (URL сайта с Vercel), опц. `HEALTHCHECK_URL` (healthchecks.io).
5. Actions → workflow `monitor` → Run workflow (первый прогон вручную).
   Дальше — по расписанию 6×/день (07–22 по Ташкенту); каждый прогон коммитит данные,
   и Vercel пересобирает сайт автоматически.

Лимиты бесплатных тарифов: GitHub Actions 2000 мин/мес (6 прогонов/день по
~5 мин ≈ 900 мин — с запасом), Vercel Hobby формально некоммерческий — для
прода перейти на Pro ($20/мес) или Cloudflare Pages (бесплатно, коммерческое ок).

## Кабинет команды (Supabase)

Закрытая часть `/app`: логин по e-mail/паролю, папки (новые / сохранённые /
в работе / поданные / выигранные), личные статусы и заметки, видно «кто ведёт».
Без ключей Supabase локально работает demo-режим, на проде кабинет закрыт.

Подключение (один раз):
1. supabase.com → New project (регион любой EU, пароль БД сохранить).
2. SQL Editor → вставить содержимое `supabase/schema.sql` → Run.
3. Project Settings → API: скопировать Project URL, anon (public) key,
   service_role key.
4. Vercel → Project → Settings → Environment Variables:
   `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` → Redeploy.
5. GitHub → Secrets → Actions: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`
   (пайплайн зеркалит тендеры в Postgres).
6. Пользователи: Supabase → Authentication → Users → Add user →
   email+пароль (Auto confirm ✓). Раздать команде.

## Дедупликация (v3)

1. **Вечный seen** по стабильным ключам: uid источника (`wb:OP…`, `tw:36300`,
   `lexuz:<id>`) → канонический URL → контент-хеш. Тендеры и НПА не протухают;
   новостные хеши чистятся через 60 дней.
2. **Реестр НПА** по реквизиту акта (`ZRU-1137`, `UP-60`, `PP-394`, `PKM-…`,
   `LEX-<id>`), извлекается regex-ом + LLM-полем `npa_ref` из любых категорий.
   Известный акт → новость становится «упоминанием» карточки, не новой записью.
3. **Семантический дедуп** (перекрытие токенов ≥ 0.45) против истории за 14 дней
   и между категориями news↔legislation, плюс внутри запуска.

## Своевременность (09.09.2026)

Лоты показываются **в день публикации**, а не в день дедлайна. Расследование по
лоту 508054: опубликован 02.09, бот увидел 09.09 — потому что раздел «Активные лоты»
etender отсортирован по дате окончания, а бот брал первую страницу (20 из ~300).
74 из 117 etender-лотов ловились в день закрытия. Исправлено переходом на API
с полной лентой; UNGM догружается прокруткой (15 → 45+ строк на страну).
В карточках Telegram и кабинете есть «📅 опубл.»; лоты с дедлайном < 24 ч в канал
не отправляются (`NOTIFY_MIN_HOURS_LEFT`), на сайте остаются с пометкой «истекает».

**Расписание (14.09.2026).** Cron `0 3,7,11,15` на «круглой» минуте GitHub задерживал
на 1–4 часа, а утренний слот 03:00 UTC не запускался ни разу за неделю (3 прогона в день
вместо 4; данные за 12 дней: старт 07:4x / 13:5x–15:0x / 17:4x–18:3x UTC). Переведено на
`17 2,5,8,11,14,17` — 6 прогонов в день, минута :17. Прогон занимает ≈ 5 минут.
Проверка: `git log --author=ta-tenders-bot --format=%ad` — должно быть 6 коммитов в день.

**Фильтр товарки (14.09.2026).** `xarid qilish` («закупить») стоит в каждом узбекском
лоте etender, а `техник` резал «техническое обследование» и «Техник топшириқ» — из-за
этого до LLM не доходили ТЭО (TIA), НИР и лойиҳа-ҳужжатлар. Убраны, добавлен узбекский
словарь услуг (`xizmat`, `ishlab chiqish`, `tadqiqot`, `iqtisodiy asos`, кириллица) —
апострофы o‘/g‘/ta’mirlash нормализуются перед сравнением. Регресс-матрица из 40
названий — в памяти проекта.

**Витрина сайта (14.09.2026).** Экспорт брал «последние 800 записей любой категории».
Новости хранятся все (для дедупа, ~150/день), поэтому окно покрывало ~5 дней и
480 живых тендеров выпали из кабинета. Теперь тендеры/НПА/позиции выбираются отдельно
(`NONNEWS_DAYS=120`, закрытые держатся ещё `EXPIRED_KEEP_DAYS=30`), новости — только
релевантные (`NEWS_LIMIT=300`). Витрина: 72 → 649 записей. Отсечённое словарями
товарки/региона больше не помечается `seen` — при смягчении словаря лоты всплывают сами;
335 залипших ключей сняты.

**TenderWeek (14.09.2026, вечер).** Шаблон `tenderweek_2026` отдаёт даты отдельными
узлами («Опубликовано», «14.09.2026»), старый regex их не видел — у всех TW-лотов были
пустые дата и дедлайн. Порог «название < 8 символов» молча выбрасывал «Аудит» (REoI на
аудит проекта ФАР) и «Услуги». Рубрик у лота может быть несколько. Исправлено; рубрики
«Консультационные услуги», «Финансовые услуги», «ПО», «Образование» помечаются
`consulting_cat`: словарь товарки не применяется, в канал уходят всегда (порог 7).
Продления («Обновлено dd.mm.yyyy», заголовок «ПРОДЛЕНИЕ: …») — новое событие: ключ seen
с датой обновления, запись на сайте перезаписывается (без дубля), в канал — карточка с новым
дедлайном. Поиск на TW: `GET /?q=&rubrika_id=` (рубрики), сортировки `?oby=date|stop`.
